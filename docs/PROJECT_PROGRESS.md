# Selected Project Progress

Project progress in the public README is maintained in `data/profile.json`.
Private repository links, local paths, unreleased source and private hardware
evidence are not published.

Percentages use a deliberately conservative calculation:

```text
fully completed top-level roadmap stages / all top-level roadmap stages
```

Partial, substantially complete, started, planned and validation-pending stages
do not count as complete. This avoids assigning subjective fractional weights.

## HackPod — 50%

The HackPod roadmap has six top-level stages: Milestones 0, 1, 2 and 3,
Phase 4, and Milestone 4. Milestones 0 and 3 are complete, and the current
roadmap records Phase 4 transport, real decoded Bluetooth audio, normal-product
scan/connect/music and automatic local-output fallback as hardware validated.
The Milestone 3 history explicitly describes Phase 4 Bluetooth as completed.
Milestone 1 retains a documented caveat, Milestone 2 remains partial, and
Milestone 4 product polish remains active, so none of those three count.

Calculation: `3 / 6 = 50%`.

## X-Link — 18%

The X-Link roadmap now has seventeen numbered milestones, 0 through 16. Its
status table marks only Milestones 0, 1 and 2 as `Complete` and states that no
milestone is marked complete while any original scope remains. The substantial
network, FTP, dashboard, Insignia, Downloader, OTA and release work is reflected
in the recruiter-facing summary, but roadmap entries labelled substantially or
partially complete, foundation started, implemented with validation pending, or
board-validated with explicit remaining scope do not count as complete.

Calculation: `3 / 17 = 17.65%`, rounded to `18%`.

These percentages describe roadmap completion only. They do not reduce or
inflate the separately documented implemented and hardware-validated features.
